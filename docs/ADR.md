# Architecture Decision Records

## 철학

읽는 시간이 긴 학습 앱이다. 기능을 늘리기보다 **개념 본문이 잘 읽히는 것**을 우선한다.
서버 없이 정적 파일로 끝나는 구조를 유지한다. 외부 의존성은 이유가 있을 때만 추가한다.

---

### ADR-001: Next.js가 아니라 Vite + React SPA
**결정**: Vite 5 + React 18 + TypeScript로 순수 클라이언트 SPA를 만든다.
**이유**: 런타임에 서버가 할 일이 없다 — 데이터는 정적 JSON이고 상태는 localStorage다.
개발 환경 Node가 18.17.1이라 Next.js 15(18.18.0 이상 요구)는 애초에 돌지 않는다.
**트레이드오프**: SSR·SEO·서버 라우트를 포기한다. 학습 앱이라 검색 유입이 목적이 아니므로 손실이 작다.
나중에 서버가 필요해지면 마이그레이션 비용을 그때 낸다.

### ADR-002: 문제 은행은 빌드 전에 확정한 정적 JSON
**결정**: 개념·문제 데이터를 harness step에서 한 번 생성해 `src/data/*.json`으로 커밋한다.
런타임 AI 생성을 하지 않는다.
**이유**: 런타임 생성은 매번 정답 신뢰도가 달라진다. 학습 앱에서 틀린 해설은 안 만드느니만 못하다.
고정된 JSON은 사람이 검수할 수 있고, API 키·비용·지연시간이 전부 사라진다.
**트레이드오프**: 문제가 169개로 고정된다. 다 풀면 새 문제가 없다.
문제를 늘리려면 데이터 파일을 고치고 다시 배포해야 한다.

### ADR-003: 사용자 상태는 localStorage만
**결정**: 진행률·정오답 기록을 localStorage에 저장한다. 계정도 서버도 두지 않는다.
**이유**: 정적 호스팅만으로 배포가 끝난다. 개인 학습 기록이라 공유·동기화 요구가 없다.
**트레이드오프**: 기기 간 동기화가 안 되고, 브라우저 데이터를 지우면 진행률이 사라진다.
시크릿 모드에서는 저장이 실패할 수 있으므로 읽기·쓰기를 전부 try/catch로 감싸고,
저장소가 없어도 앱은 정상 동작해야 한다.

### ADR-007: GitHub Pages 배포 — HashRouter + 상대 경로 base
**결정**: `vite.config.ts`에 `base: './'`를 두고, 라우터는 `HashRouter`를 쓴다.
URL은 `/#/topic/s3-storage-classes` 형태가 된다.
**이유**: GitHub Pages는 정적 파일 서버라 SPA fallback이 없다. `BrowserRouter`로 만들면
`/topic/s3`에 직접 들어가거나 새로고침할 때 404가 난다. 흔한 우회책인 `404.html` 복사 트릭은
브라우저가 404를 한 번 받고 리다이렉트하는 구조라 깜빡임이 생기고, 저장소 이름이 바뀌면
`base` 설정도 따라 고쳐야 한다. `HashRouter` + `base: './'`는 **배포 설정이 0**이고
저장소 이름·서브경로에 무관하게 동작한다.
**트레이드오프**: URL에 `#`이 붙어 보기 나쁘고 검색엔진 색인에 불리하다.
개인 학습 앱이라 둘 다 비용이 작다. 나중에 커스텀 도메인을 붙이면 `BrowserRouter`로 바꿀 수 있다.

### ADR-004: react-router-dom을 쓴다
**결정**: 화면 전환을 `useState`가 아니라 URL 라우팅으로 처리한다.
**이유**: 개념을 읽다가 문제로 갔다가 다시 개념으로 돌아오는 흐름이 핵심이다.
브라우저 뒤로가기가 동작하지 않으면 이 흐름이 깨진다. 주제 URL을 북마크할 수도 있어야 한다.
**트레이드오프**: 의존성이 하나 늘고, 정적 호스팅 시 SPA fallback 설정이 필요하다.
상태 기반 전환보다 초기 코드가 조금 많지만, 뒤로가기를 직접 구현하는 것보다 싸다.

### ADR-005: 4지선다 단일정답으로 고정
**결정**: 모든 문항은 보기 4개, 정답 1개다. 복수정답·순서맞추기 등을 만들지 않는다.
**이유**: 이 앱의 문제는 시험 재현이 아니라 개념 점검 수단이다.
형식이 하나면 채점 로직과 UI가 단순해지고, 문제 은행 품질에 집중할 수 있다.
**트레이드오프**: 실제 SAA-C03에 나오는 복수정답 유형에는 대비되지 않는다.
시험 직전 실전 감각은 다른 자료로 보완해야 한다.

### ADR-006: 원본 텍스트를 유일한 출처로 삼는다
**결정**: 개념 본문과 문제는 `docs/source/concepts-raw.md`에서만 만든다.
모델이 알고 있는 AWS 지식을 끌어와 보강하지 않는다.
**이유**: 원본은 사용자가 고른 학습 자료다. 앱이 원본에 없는 걸 가르치면
"이 자료 한 권으로 끝낸다"는 전제가 깨지고, 검수 기준도 사라진다.
**트레이드오프**: 원본이 다루지 않는 주제는 앱에도 없다. 원본의 오류도 그대로 따라간다.
명백한 오탈자는 추출 단계에서만 교정하고, 내용 보강은 하지 않는다.
