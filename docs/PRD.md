# PRD: AWS SAA-C03 개념 학습 앱

## 목표

SAA-C03 범위의 AWS 서비스 개념을 주제 단위로 읽고, 읽은 자리에서 바로 확인 문제로
이해도를 점검한다. **문제를 많이 푸는 앱이 아니라 개념이 남는 앱을 만든다.**

## 사용자

SAA-C03을 준비하는 사람. AWS 서비스 이름은 들어봤지만 "언제 무엇을 쓰는지"가
정리되지 않은 상태. 짧게 여러 번 들여다보며 개념을 눌러 담는 방식으로 공부한다.

## 원본

`docs/source/concepts-raw.md` — 원본 PDF에서 추출한 22개 주제의 개념 정리.
각 주제에는 원본이 매긴 중요도(★★★ / ★★☆)가 붙어 있다.
개념 본문과 문제는 전부 이 문서에서만 나온다.

## 핵심 기능

1. **주제 목록** — 20개 주제를 중요도와 함께 보여준다. 각 주제의 학습 상태(안 봄 / 읽음 / 점검 완료)를 표시한다.
2. **개념 읽기** — 주제 하나의 개념을 처음부터 끝까지 읽는 화면. 서비스별로 "한 줄 요약 → 설명 → 특징" 순서로 정리한다.
3. **확인 문제** — 개념을 읽은 뒤 그 주제의 문제를 푼다. 4지선다 단일정답. 문항과 보기 순서는 열 때마다 섞인다. 답을 고르면 즉시 정오 표시 + 해설, 그리고 근거가 된 개념으로 돌아가는 링크.
4. **복습** — 틀린 문항을 오답노트에 모아 두고, 그 문항만 다시 푼다. 문항마다 근거 개념으로 가는 링크가 붙는다. **한 번 틀리면 사용자가 지울 때까지 남는다** — 다시 풀어서 맞혔다고 자동으로 빠지지 않는다. 근거는 ADR-017.
5. **진행률** — 주제별 / 전체 학습 진행 상황. localStorage에 저장해 브라우저를 닫아도 유지된다.
6. **랜덤 문제** — 주제와 무관하게 전체 문항에서 10 / 20 / 30 / 50 / 100개나 전체를 무작위로 뽑아 푼다. 푸는 화면과 기록은 확인 문제와 같고, 다른 것은 문항을 고르는 범위뿐이다. 주제 이름이라는 힌트 없이 서비스를 구분할 수 있는지 점검하는 용도다. 근거는 ADR-012.
7. **검색** — 개념 이름·한 줄 요약·본문과 주제 제목에서 찾는다. 결과는 그 개념이 속한 주제의 개념 읽기로 이어진다. 개념 182개는 주제 제목만 봐서는 어디 있는지 알 수 없기 때문이다. **문항은 검색하지 않는다** — 문제문과 해설이 결과에 뜨면 확인 문제가 무의미해진다. 근거는 ADR-013.

## MVP 제외 사항

- 모의고사 · 제한시간 · 점수 산출. 이유: 시험 리허설은 이 앱의 목적이 아니다.
  랜덤 문제(핵심 기능 6)는 이 선 안쪽이다 — 범위만 전체로 넓힌 확인 문제이고,
  제한시간도 합격선도 점수 이력도 두지 않는다. 셋 중 하나라도 붙는 순간 이 제외 사항을 어긴 것이다.
- 복수정답 문제. 이유: 4지선다 단일정답으로 고정한다.
- 계정 · 로그인 · 서버 · 기기 간 동기화. 이유: 서버를 두지 않는 게 배포 전략이다.
- 런타임 AI 문제 생성. 이유: 문제 은행은 빌드 전에 확정해 JSON으로 커밋한다.
- 검색 — **ADR-013으로 개정됐다. 핵심 기능 7을 봐라.** 원래 사유는 "20개 주제는 목록으로
  훑는 게 더 빠르다"였고, **주제에 대해서는 지금도 맞다**(주제 목록에 필터를 붙이지 마라).
  개정한 것은 그 20개 안에 든 **개념 182개를 이름으로 찾는 경로** 하나뿐이다.
  문항 본문·해설 검색은 여전히 제외다.

## 문제 은행

- 총 169문항 목표. 22개 주제에 **중요도 비례로 배분**한다(★★★ 주제에 더 많이).
- 전부 `docs/source/concepts-raw.md`의 내용에서 출제한다. 원본에 없는 AWS 지식을 끌어오지 마라.
- 각 문항은 반드시 근거 개념(주제 id + 서비스명)을 필드로 갖는다. 해설에서 개념으로 되돌아가기 위해 필요하다.
- 오답 선택지도 원본에 등장하는 다른 서비스에서 고른다. 그래야 "헷갈리는 짝"을 구분하는 연습이 된다.
- **정답 계열을 가리키는 키워드는 문제문에 일관되게 넣되, 그 키워드만으로 답이 정해지게 두지 마라.**
  예: Glacier 계열이 정답인 문항은 모두 문제문에 법·감사(·규정) 목적을 담는다(원본 PAGE 8 근거).
  대신 그런 문항의 보기에는 **Glacier 보기를 둘 이상** 두어, 최종 판단은 조회 시간 같은 실제
  변별 축이 하게 한다. 보기 중 Glacier가 하나뿐이면 키워드가 곧 정답이 되어 문항이 무의미해진다.
- **키워드를 부정형으로 쓰는 대조 문항을 함께 둔다.** q018("법·감사 목적의 장기 보관은 아니면서",
  정답 S3 Standard-IA)이 그것이다. 이런 문항이 있어야 "법이 보이면 무조건 Glacier"라는
  잘못된 암기가 걸러진다. 지우지 마라.

## 디자인

- 다크모드 고정. 미니멀.
- 무채색 기반. 색은 정답/오답/중요도 표시에만 쓴다.
- 읽는 시간이 긴 앱이다. 본문 가독성(줄간격·최대 너비)을 화려함보다 우선한다.
- 상세 규칙은 `docs/UI_GUIDE.md`.
