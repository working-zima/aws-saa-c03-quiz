# phase 60 실측 기록 — 가로형 도식 시범 3장

측정일 2026-10-15. `feat-60-wide-diagrams`(`f73efb7`)의 `npm run build` 결과를 `vite preview`로 띄워 macOS Chrome에서 쟀다.
비교 대상 develop(`999cf51`)도 같은 방법으로 띄웠다. 1440px은 창 자체에서, 나머지 폭은 같은 출처 iframe의 폭을 바꿔 쟀다
(Chrome 창 크기 조절이 이 환경에서 먹지 않는다 — phase 58과 같다).

- **표시 폭·높이**: `svg.getBoundingClientRect()`.
- **배율**: 표시 폭 ÷ `viewBox` 폭. 노드 글자는 10 × 배율, 그룹 글자는 9 × 배율이다.
- **가장 빠듯한 여백**: 노드마다 `rect` 폭 − 글줄의 `getComputedTextLength()` 가운데 가장 작은 값(`viewBox` 단위). 테스트의 기준은
  `estimateTextWidth + 12 <= 폭`이고, 실측 여백이 12보다 크면 실제 글꼴로도 들어간다.
- **가로 넘침**: `documentElement.scrollWidth > clientWidth`.

## 재지 못한 것

- **창 폭을 바꿀 때의 실시간 전환**: 이 환경의 Chrome 탭이 `visibilityState: hidden`이라 렌더링 단계가 돌지 않아 `matchMedia`의 `change`가
  발생하지 않았다(iframe 폭을 700→800px로 바꿔도 세로형 그대로). 전환과 선택 유지는 도식마다 단위 테스트(모의 `change` 이벤트)가 확인한다.
- 확인 문제의 「개념 보기」 안의 도식: 같은 `max-w-2xl` 섹션 안이라 폭은 개념 읽기와 같다. 따로 재지 않았다.
- Windows Chrome 글꼴: 재지 않았다.
