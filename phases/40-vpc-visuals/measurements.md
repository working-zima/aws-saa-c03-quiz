## 캡션 줄 수

시나리오를 하나씩 눌러 `figcaption` 글자의 줄 수를 셌다. 320px / 390px.

| 도식 | 안내(전체) | 시나리오들 |
|---|---|---|
| 지도 | 1 / 1 | 모두 2줄 이하 |
| 목적지별 흐름도 | 2 / 1 | 인터넷 3/3, AWS 서비스 **4**/3, 다른 VPC의 앱 3/2, 다른 VPC 전체 3/2 |
| 피어링 | **4** / 3 | VPC 3개 3/3, VPC 6개 **4**/3, VPC 10개 **4**/4 |
| NAT 개수 실험 | 2 / 2 | 셋은 2/2, 개발 · AZ A 장애 3/3 |
| 존재 단위(정적) | 5 / 4 | – |

- **step 문서의 "두 줄을 넘기지 마라"를 흐름도·피어링·NAT의 캡션 일부가 어긴다.** 다만 가장 긴 것이
  4줄(96px)이라 `figcaption`의 `min-h-24`(96px)를 넘지 않는다. **시나리오를 바꿔도 아래 본문이 움직이지 않는다.**
- 존재 단위 도식은 정적 도식이라 캡션이 바뀌지 않는다. 5줄은 레이아웃 흔들림과 무관하다.

## 약어 툴팁

- 약어 버튼은 다섯 자리다. `IAM`(vpc-endpoint-policy), `ACL`(s3-is-regional), `EC2`(nat-instance, comparison —
  개념마다 첫 등장), `VPN`(vpc-peering-scaling-limit). 도식·표 안에는 없다.
- 누르면 `role="tooltip"`이 뜨고 버튼의 `aria-describedby`가 그 id와 같다. `Escape`로 닫힌다.
- 320px에서 툴팁 폭 288px, 왼쪽 8px에 붙잡힌다(앵커 x=20·71에서 모두 L8 R296). ACL은 L19 R307.
  1280px에서는 앵커 가운데에 맞는다.

## 눈으로 확인한 것 (390px)

- **지도 `Transit Gateway`**: `EC2` → 오른쪽 통로 → `Transit Gateway` → `다른 VPC의 앱`. 아래쪽 두 번째
  `프라이빗 서브넷` 박스(엔드포인트 둘을 담음)는 별도 서브넷으로 읽혀 어색하지 않다.
- **NAT `개발 · AZ A 장애`**: 가용 영역 A 옆에 곁말 `장애`, A의 두 노드와 NAT B·C가 흐리고, EC2 B·C는
  선명한데 나가는 선이 없다. 빨강 없음.
- **피어링 `VPC 10개`**: 메시 45선과 허브 10선이 위아래로 대비되고 `연결 45개`/`연결 10개` 곁말이 캡션과 같다.
  VPC 상자끼리 겹치지 않는다.

## 완료 뒤 고친 둘 (2026-09-26, 사용자 승인)

위 표들은 고치기 **전** 값이다. 고친 뒤 다시 쟀다.

**1. 캡션 길이.** 흐름도 넷, 피어링의 안내와 셋, NAT `개발 · AZ A 장애`를 줄였다. 피어링 캡션은 테스트가 요구하는
전제("모든 VPC가 서로 통신해야 한다면")와 연결 수를 그대로 담는다. 다시 잰 결과 **모든 시나리오 캡션이 320px에서
2줄 이하**다(흐름도 2·2·2·2, 피어링 안내 2·셋 2·2·2, NAT 넷 모두 2). 정적인 존재 단위 도식의 안내만 5줄로 남겼다 —
바뀌지 않는 캡션이라 레이아웃이 흔들리지 않는다.

**2. 비교표 열 폭.** 표에 선택 필드 `columnWidths`를 더해 `colgroup`으로 나눈다. 「무엇을 어디에 붙이나」는
36% / 16% / 48%(판정 열이 가장 좁다), 나머지 넷은 24% / 38% / 38%(행 머리 열을 좁힌다).
