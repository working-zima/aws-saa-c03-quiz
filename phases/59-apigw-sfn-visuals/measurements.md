## 눈으로 확인한 것 (갤러리 캡처, 도식 폭 390·표 폭 288)

- 통합 방식 `Lambda 프록시`: 요청선이 클라이언트에서 API Gateway 박스를 지나 Lambda 함수로 내려가고, 응답선이 그 왼쪽에서 클라이언트 왼쪽 변으로
  올라간다. 두 곁말이 두 선의 양옆에 붙는다. `매핑 템플릿`: 매핑 템플릿에서 오른쪽 통로로 내려가 백엔드 오른쪽 변으로 들어간다.
  `JSON을 XML로`: 요청선 옆에 `JSON`, Lambda 함수에서 백엔드로 꺾이는 선 옆에 `XML`이 붙고 매핑 템플릿이 흐리다.
- 엔드포인트 경로 `리전`·`API 캐싱`: 사용자에서 오른쪽 통로로 엣지 박스 바깥을 돌아 API Gateway 오른쪽 변으로 들어간다. step 2가 엣지 박스 폭을
  256으로 줄여(x 4..260) 이 선이 엣지 박스를 지나지 않는다. `CloudFront 오리진`: CloudFront에서 S3 버킷과 API Gateway로 두 선이 내려간다.
- 상태 머신 `업로드로 시작`: S3 버킷 → EventBridge 규칙 화살표, 규칙에서 꺾여 첫 태스크로 내려가는 선이 그룹 라벨 `상태 머신` 오른쪽을 지난다.
  `실패하면 재시도`: 첫 태스크 아래 변에서 나와 다시 들어가는 고리. `Lambda 하나로`: 상태 머신 노드가 모두 흐리고 맨 아래 노드만 선명하다.
- Map 상태 `Map 상태`: 목록 오른쪽 변에서 나와 꺾여 Map 상태로 내려가는 선이 그룹 라벨 `상태 머신`을 가로지르지 않는다.
- 선이 노드 글자나 그룹 라벨을 가리는 곳이 없다. 이모지·빨강·애니메이션이 없다.
