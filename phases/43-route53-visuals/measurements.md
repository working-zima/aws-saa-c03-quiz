# Route 53 시각 요소의 브라우저 실측 (2026-09-27)

phase 40~42와 같은 방법이다. worktree(`../aws-saa-c03-quiz-p43`)에서 빌드 후 `vite preview`를 띄우고 Claude in Chrome으로
고정 폭 iframe(320×900, 390×900, 1280×900)에 `/#/topic/route53`을 열어 `getBoundingClientRect()`를 읽었다.
**이 파일에 없는 숫자를 지어내지 마라.**

## 공통

| 항목 | 320px | 390px | 1280px |
|---|---|---|---|
| 문서 가로 넘침 | **없음** (scrollWidth 320) | **없음** (390) | **없음** (1280) |
| 도식 SVG 표시 폭 | 320px | 380px | 380px |
| figure 안 가로 넘침 | 없음 | 없음 | 없음 |
| 시나리오 버튼 최소 높이 | 44px | 44px | 44px |
| console error | 0 | 0 | 0 |

주제 안 figure 순서: 비교표(`routing-policies` 뒤) → 상태 도식(`multivalue-answer-details` 뒤) → 별칭 도식
(`route53-alias-record` 뒤) → 하이브리드 DNS 도식(`private-hosted-zone-vpc-only` 뒤).

## 도식·표별

버튼 줄과 figure 높이는 320 / 390 / 1280px이고, `전체` 상태에서 쟀다.

| 요소 | `viewBox` | 버튼 줄 | figure 높이 |
|---|---|---|---|
| 표: Route 53 라우팅 정책 비교 | – | – | 478 / 454 / 430 |
| 상태 검사와 Route 53 응답 | `0 0 280 244` | 44 / 44 / 44 | 537 / 573 / 557 |
| 별칭 레코드 | `0 0 280 256` | 96 / 44 / 44 | 587 / 573 / 573 |
| 하이브리드 DNS 방향 | `0 0 280 340` | 96 / 96 / 44 | 683 / 755 / 687 |

비교표 열 폭은 320px에서 86 / 202px, 390px에서 107 / 251px, 1280px에서 191 / 447px이다(30% / 70%).

## 캡션 줄 수

모든 시나리오(`전체` 포함)를 하나씩 눌러 `aria-live` 캡션 글자의 줄 수를 셌다. **320px·390px에서 모두 2줄, 1280px에서 모두 1줄**이다.
50자를 넘는 캡션(별칭 `direct-ip` 54자, 하이브리드 DNS 52~57자)도 320px에서 2줄이다.

## 라벨의 실제 폭

SVG `text`의 `getBBox()` 오른쪽 끝 최댓값: 상태 도식 227.5, 별칭 도식 218.7, 하이브리드 DNS 도식 244.4. 모두 viewBox 폭 280 안이다.

## 눈으로 확인한 것 (390px)

- 상태 도식 `단순`: Route 53에서 흐린 리전 A로 화살표가 그대로 내려가고, 아래에 `비정상`이 붙는다. `페일오버`: 화살표가 리전 B로
  가고, 리전 A 위에 `주 · 상태 검사`, 리전 B 위에 `보조`가 붙는다.
- 별칭 도식 `인스턴스 교체`: 도메인 이름 → ALB → 새 EC2로 내려가고, 흐린 EC2 아래에 `교체됨`, 도메인 이름 옆에 `레코드 그대로`가 붙는다.
  `공용 IP에 직접`: 오른쪽 옆 통로로 ALB를 비켜 EC2에 닿는다.
- 하이브리드 DNS `규칙 공유`: 두 VPC의 EC2 경로가 행 사이 통로에서 합쳐져 아웃바운드 엔드포인트 → 사내 DNS 서버로 올라간다.
  `인바운드`: 사내 서버 → 인바운드 엔드포인트 → 가운데 통로 → 프라이빗 호스팅 영역으로 내려가고, 아래에 `app.internal.aws`가 붙는다.
  엔드포인트는 Resolver 박스 안, VPC 박스 밖에 있다. 선이 노드 글자를 가리지 않는다.
