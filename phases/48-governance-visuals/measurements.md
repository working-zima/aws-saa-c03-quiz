phase 43과 같은 방법이다. worktree(`../aws-saa-c03-quiz-p48`)에서 빌드한 뒤 `vite preview`(포트 4178)를 띄웠다. Claude in Chrome으로

console error는 0이다. 페이지를 새로 불러온 뒤 모든 시나리오 버튼을 눌러 확인했다.

## 도식·표별

버튼 줄과 figure 높이는 320 / 390 / 1280px 순서이고, `전체` 상태에서 쟀다. 시나리오를 바꿔도 figure 높이는 변하지 않았다.

| 요소 | `viewBox` | 버튼 줄 | figure 높이 |
|---|---|---|---|
| 표: 도구별 고를 때와 헷갈리는 짝 | – | – | 845 / 701 / 533 |
| 드리프트 감지와 AWS Config 범위 | `0 0 280 276` | 44 / 44 / 44 | 605 / 649 / 649 |
| Control Tower 제어 시점 | `0 0 280 240` | 96 / 96 / 44 | 616 / 668 / 600 |

비교표의 열 폭(머리 칸 `th` 기준)은 다음과 같다(41% / 24% / 35%).

- 320px: 118.1 / 69.1 / 100.8px
- 390px: 146.8 / 85.9 / 125.3px
- 1280px: 261.6 / 153.1 / 223.3px

## 표의 줄바꿈

칸마다 공백으로 나눈 단어를 `Range.getClientRects()`로 재서, 한 단어가 두 줄에 걸치는지 봤다.

- 영문 이름(`CloudFormation`·`Organizations`·`Service`·`Catalog`·`Config`·`X-Ray` 등)은 세 폭 모두에서 **끊기지 않는다**.
  칸 안 가로 넘침(`scrollWidth > clientWidth`)도 없다.
- **320px에서 한글 단어 하나가 중간에서 끊긴다**: `달라졌는지` → `달라졌는` / `지` (드리프트 감지 행, `고를 때` 칸).
  `고를 때` 칸의 글자 폭은 60px 남짓이라 다섯 음절 단어가 들어가지 않는다. 390px·1280px에서는 끊기지 않는다.
  - 같은 칸 문구를 `템플릿과 다른지 볼 때`로 바꿔 320px에서 재 보면 `템플릿과` / `다른지 볼` / `때`로 끊김이 없고 figure 높이(845)도 같다.
    **아직 반영하지 않았다** — 사용자 결정 대기.
- 가운뎃점 뒤에서 줄이 바뀌는 곳이 셋 있다(320px만): `추적·` / `감사는`, `통제·` / `로깅을`, `사용자·` / `역할`. 단어 경계라 끊김으로 세지 않는다.

## 캡션 줄 수

`전체`를 포함해 모든 시나리오를 하나씩 눌러 `aria-live` 캡션 글자의 줄 수를 셌다. **320px·390px에서 모두 2줄, 1280px에서 모두 1줄**이다.

| 도식 | 시나리오(글자 수) |
|---|---|
| 범위 | 전체(37), 드리프트 감지(47), AWS Config(42) |
| 제어 시점 | 전체(40), 사전 예방적 제어(48), 탐지 제어(46), 탐지 후 자동 수정(49) |

## 라벨과 곁말의 실제 폭

SVG `text`의 `getBBox()` 가로 범위(viewBox 단위)다.

- `전체` 상태 글자의 오른쪽 끝 최댓값: 범위 도식 234.7, 제어 시점 도식 238.9. 왼쪽 끝 최솟값은 둘 다 14다.
- 곁말: `not-seen` 226..260, `all-resources` 208..268, `not-created` 49..91, `report-only` 164..256, `exists-until-fixed` 36..104,
  `auto-fix` 179..241. 모두 viewBox 폭 280 안이다.

## 눈으로 확인한 것 (390px)

- 범위 도식 `드리프트 감지`: 템플릿에서 스택의 첫 리소스로, 드리프트 감지에서 스택 박스 아래 변으로 화살표가 간다. `스택 밖` 리소스 둘과
  AWS Config가 흐려지고, `스택 밖` 라벨 줄 오른쪽에 `보지 못함`이 붙는다.
- 범위 도식 `AWS Config`: AWS Config에서 두 갈래 화살표가 스택과 스택 밖 박스 아래 변으로 간다. 템플릿과 드리프트 감지가 흐려지고,
  `한 계정` 라벨 줄 오른쪽에 `모든 지원 리소스`가 붙는다.
- 제어 시점 도식 `사전 예방적 제어`: 배포가 사전 예방적 제어로 내려가 `스택 작업 거부`로 꺾인다. `만들어진 뒤` 띠의 두 노드가 흐려지고
  리소스 아래에 `생기지 않음`이 붙는다.
- `탐지 제어`·`탐지 후 자동 수정`: 배포가 흐려진 두 노드 사이 통로로 위쪽 띠를 지나 리소스에 닿고, 탐지 제어의 화살표가 리소스를 가리킨다.
  곁말만 다르다(`찾아서 보고 · 지우지 않음` / `고치기 전까지 존재`·`탐지 뒤 자동 수정`).
- 선이 노드 글자를 가리지 않는다.
