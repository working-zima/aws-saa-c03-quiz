# 도식 다섯의 브라우저 실측 (2026-09-20)

**step 6이 UI_GUIDE 「도식」 절에 적을 숫자는 여기서 가져온다.** 추정치가 아니라 실측이다.

## 잰 방법

harness를 돌린 worktree에서 `npm run dev`를 띄우고, Claude in Chrome으로
**고정 크기 iframe**(320×900, 390×900)과 1280px 창에서 쟀다. iframe을 쓰는 이유는
창 크기 변경이 이 환경에서 뷰포트에 반영되지 않았기 때문이고, 이 저장소가 전에 쓰던 방법이다.

읽은 값은 `getBoundingClientRect()`이고, 라벨 크기는 `SVG 표시 폭 ÷ viewBox 폭 × 글자 크기`다.

## 전 도식 공통

| 항목 | 값 |
|---|---|
| `viewBox` 폭 | **280** (다섯 장 모두) |
| SVG 표시 폭 — 320px 뷰포트 | **320px** (배율 1.143) |
| SVG 표시 폭 — 390px 이상 | **380px** (`max-w-[380px]` 상한, 배율 1.357) |
| 노드 라벨(글자 크기 10) — 320px | **11.43px** |
| 노드 라벨 — 390px 이상 | **13.57px** |
| 그룹 라벨(글자 크기 9) — 320px | **10.29px** |
| 그룹 라벨 — 390px 이상 | **12.21px** |
| 가로 넘침 | **없음** (320·390·1280px 전부) |
| 버튼 최소 높이 | **44px** (UI_GUIDE 「터치 영역」 충족) |

**`viewBox` 폭 280은 1:1 비율이 아니라 좌표계의 약속이다.** 320px 뷰포트에서 실제 표시 폭이
320px인 것은 `DiagramFrame`이 모바일에서 좌우 여백을 뚫기 때문이다
(`figure`에 `-mx-5 sm:mx-0`, SVG 래퍼에 `-mx-4 sm:mx-0` + `max-sm:w-[calc(100%+2rem)]`).
`w-full`은 음수 마진만으로 늘어나지 않아 마지막 것이 필요했다.

## 눈으로 확인한 것 — 다섯 장 전부

- **VPC 통신 경로**: `VPC → S3`를 고르면 EC2 → 게이트웨이 엔드포인트 → S3만 켜지고,
  S3가 VPC 밖·리전 안에 있다는 것이 배치로 드러난다. `프라이빗 → 인터넷`도 확인했다
  (320px에서도 EC2 → NAT → IGW → 인터넷이 또렷하다).
- **온프레미스 연결 경로**: `Direct Connect`를 고르면 `인터넷`이 흐려진 채
  `Direct Connect 위치` **바로 옆 같은 높이에** 남는다. 전용선이 인터넷을 지나지 않는다는 것이
  글이 아니라 위치로 읽힌다. 캡션이 "암호화는 해 주지 않는다"는 함정을 함께 싣는다.
- **엣지에서 오리진까지**: `리전 장애 조치`에서 `Route 53`이 엣지 그룹 **밖에** 흐려진 채 남고
  경로는 뷰어 → Global Accelerator → 리전 B의 NLB로 간다. `리전 A` **안의 노드들이**
  흐려져 "리전이 바뀌었다"가 보인다 — 그룹 박스 자체는 흐려지지 않는다(지도의 틀이므로).
- **S3 스토리지 클래스 분류**: `대기 조회` 안에서 `장기 보관 목적` 바깥 칸이 비어 있는 것이
  그대로 보인다. 비용 줄이 근거 있는 관계만 적고
  "나머지끼리의 순위는 이 주제가 다루지 않는다"로 끝난다.
- **보안 그룹과 네트워크 ACL 경계**: 위쪽 그림에서 보안 그룹 경계가 네트워크 ACL 경계 안에
  들어가 적용 범위 차이가 보이고, `그 응답`을 고르면 **`보안 그룹 아웃바운드`만 점선**이 되어
  "규칙 없이 통과한다"가 색이 아니라 형태로 드러난다.
- 모바일에서 카드가 화면 끝까지 차되 좌우 테두리가 없어 잘린 느낌이 나지 않는다.

## 경로·노드 교차 — 기계로 덮었다

도식 테스트는 `rect`가 viewBox 안에 있는지와 라벨이 상자에 들어가는지만 본다.
**경로선이 무관한 노드를 뚫고 지나가는 것**은 그 둘이 보지 못해 눈으로만 알 수 있었다.
다섯 도식의 경로가 전부 직교(M/H/V)라서 산술로 정확히 판정할 수 있고,
`tools/check-path-crossings.mjs`가 그것을 한다. 상자 경계에 닿는 것은 연결 지점이므로
교차로 세지 않고, 내부를 지나는 선분만 잡는다. 노드끼리의 상자 겹침도 함께 본다.

```
✓ 교차 없음 — 노드 43개, 경로 42개를 검사했고 상자 내부를 지나는 선분이 없다
```

**검사기가 실패할 수 있음을 먼저 보였다.** `VpcPathsDiagram`의 사본에 `ec2`
(x 148..256, y 532..564) 한가운데를 지나는 `M140 548 H270`을 주입하니 그 선분을 지목하고
exit 1로 끝났다. 통과만 하는 검사기는 검사가 아니다.

## 남은 한계

- `text`의 실제 폭은 `estimateTextWidth`의 어림값이다. 라벨이 상자 안에 들어가는 것은
  기계로도 눈으로도 확인했지만, 이 어림값은 글꼴이 바뀌면 함께 틀린다.
- 확인한 시나리오는 도식마다 한둘이다(다섯 장 합쳐 여섯). 나머지 시나리오는 같은 구조를
  쓰고 단위 테스트가 노드·경로 집합을 단언하므로 별도로 열어 보지 않았다.
