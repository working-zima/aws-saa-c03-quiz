# Step 4: complete-indent

## 배경 — 옮긴 JSX의 들여쓰기가 두 단계 어긋나 있다

step 1에서 `QuizPage`의 완료 화면 JSX를 `renderComplete` 콜백 안으로 옮겼는데,
**옮기기 전의 들여쓰기가 그대로 남았다.** 콜백 안으로 두 단계 더 들어갔으므로
그만큼 밀려 있어야 하는데 바깥쪽 기준에 맞춰져 있다.

`npm run lint`는 통과한다 — 이 프로젝트 ESLint 설정에 들여쓰기 규칙이 없기 때문이다.
그래서 사람이 읽을 때만 드러난다.

**이 step은 공백만 고친다. 다른 것은 아무것도 바꾸지 마라.**

## 읽어야 할 파일

- `src/pages/QuizPage.tsx` — 고칠 파일. **이 파일 하나뿐이다.**

## 고치는 것

`QuizPage.tsx`의 `renderComplete={(correctCount, total) => { ... }}` 안에 있는
`return (` 부터 `)` 까지의 JSX 블록이다. `<section>`으로 시작해 `</section>`으로 끝난다.

그 블록 전체를 **감싸고 있는 `return (` 에 맞춰 다시 들여써라.** 블록 안의 상대적인
계단 모양(중첩 깊이에 따른 단차)은 지금 그대로 유지한다 — 전체를 통째로 밀기만 하면 된다.

## 하지 마라

- **문자·토큰을 하나도 바꾸지 마라.** 공백 외의 변경은 전부 위반이다.
  변수명·클래스 문자열·JSX 구조·따옴표·줄바꿈 위치를 건드리지 마라.
- 코드를 재배치하지 마라. `hasIncorrectAnswer`를 위로 올리거나 JSX를 별도 함수로
  빼내지 마라. 그런 정리가 필요해 보여도 이 step의 범위가 아니다.
- **다른 파일을 열지도 고치지도 마라.** `src/components/`·`src/pages/`의 나머지 파일,
  테스트 파일, 설정 파일 전부 대상이 아니다.
- 새 파일을 만들지 마라. 테스트를 추가하지 마라 — 동작이 바뀌지 않으므로 테스트할 것이 없다.
- Prettier 같은 포매터를 설치하거나 실행하지 마라. 이 프로젝트에는 포매터가 없다.
  손으로 공백만 맞춘다.

## 검증 절차

아래를 전부 실행해 통과를 확인한 뒤 끝내라.

```bash
npm run test
npm run lint
npm run build
```

구조 확인 — 기대값이 옆에 적혀 있다.

```bash
git diff --name-only                  # src/pages/QuizPage.tsx 한 줄만
git diff -w --stat                    # 결과 없음
```

**`git diff -w`가 비어 있다는 것이 "공백만 바꿨다"의 증명이다.** 여기에 무엇이든 나오면
공백 외의 것을 건드린 것이다. 그 변경을 되돌려라.

**검증 조건과 올바른 코드가 충돌하면 코드를 비틀지 말고 `blocked`로 멈추고 사유를 적어라.**
